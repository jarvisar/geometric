1. **Invalid settings can break startup.** Import a JSON file containing `{"paper":null}`. The app reports that loading failed, but `state.paper` has already become null. In the reload test, this invalid state was also saved. Reloading then throws in `applyPaperSize()` before the UI is wired, leaving a blank drawing and no useful recovery message. This is more serious than just accepting a bad file because it survives reload.

   A separate harmless test importing `{"paper":{"__proto__":{"qaPolluted":true}}}` made `({}).qaPolluted` return true. The recursive merge walks inherited properties. The same merge handles shared settings. This confirms prototype pollution; it does not establish script execution or data theft.

   Validate types, finite numbers, ranges, generator IDs, and allowed keys before changing live state. Reject prototype-related keys, require own properties, and keep the previous state if validation or rebuilding fails. Validate saved state at startup too, with a recovery path.

   Code: [mergeInto](src/app.js#L131), [applyShared](src/app.js#L198), [loadSettingsFile](src/app.js#L1195), [loadInitialState](src/app.js#L1428). Evidence: [broken startup screenshot](shots/qa-2026-09-29/transactions/invalid-settings-reload.png), `transactions.steps.js`, `deep.steps.js`.

2. **Grid output escapes the sheet.** On A4 portrait with 15 mm margins, use Maze, eight columns, ten rows, a 40 mm gutter, and a frame. Every value is permitted by the UI. Output reaches x = 303 mm and y = 385 mm on a 210 × 297 mm sheet. There were 923 vertices outside the sheet in the reproduction.

   Cell dimensions are clamped to at least 1 mm, but the gutter stays unchanged. Cells are consequently placed beyond the available area. Clipping happens against each cell rather than the final paper bounds. Constrain gutters and grid dimensions together, then enforce final drawing-area bounds before export. Show the actual accepted values in the controls.

   Code: [grid sizing](src/lib/pipeline.js#L283), [cell placement](src/lib/pipeline.js#L305). Evidence: [overflow screenshot](shots/qa-2026-09-29/deep/grid-overflow.png), `deep.steps.js`.

3. **Snapshots are saved but inaccessible.** Press S or click Save snapshot, then open the Snapshots section. Local storage contains the snapshot, but `#snapGrid` contains zero cards. This also affects the empty-state message.

   `buildSnapshotsSection()` calls `renderSnaps()` before its section is attached to the document. `renderSnaps()` searches the document for `#snapGrid`, finds nothing, and returns. Populate the supplied grid directly or render after attaching the section. Existing stored snapshots should become visible without migration.

   Code: [panel attachment](src/app.js#L810), [snapshot section](src/app.js#L901). Evidence: [snapshot screenshot](shots/qa-2026-09-29/deep/snapshots.png), `deep.steps.js`.

4. **Saved recipes do not fully reproduce the drawing.** Set Spirograph's simplify tolerance to 0.5 mm and hide Pen 2. Export an SVG, reset everything, and import it. The pen becomes visible again and the simplified geometry changes. `shareable()` omits optimization settings and pen visibility. SVG metadata, share links, and snapshots all use that incomplete recipe. JSON export adds optimization settings separately but still omits visibility.

   Imports also inherit omitted fields from the recipient's current state. The same shared drawing can therefore look different in two browsers. Use one complete, versioned recipe across all four save/share routes, with explicit defaults for older recipes. Add a round-trip test that compares visible geometry, pen settings, and optimization settings.

   Code: [shareable](src/app.js#L189), [export routes](src/app.js#L1145). Evidence: `deep.steps.js`.

5. **Exports are not consistent snapshots of the drawing.** Two cases reproduced:

   - Change a parameter and export while the scheduled regeneration is pending. The SVG metadata contains the new parameter, but the path data is from the previous result. The test changed Spirograph's ring teeth to 80 and exported in the same event turn.
   - Export eight individual pen SVGs, then change the seed during the 2.1-second batch. The first two files used seed 1 in their names and recipes; the remaining six used the new seed. All callbacks retained the original geometry. Pen colors and widths are also read from live state inside the delayed callbacks.

   Track the revision used to produce each result. Export only matching geometry and settings, and capture names, paper, pens, and metadata once for an entire batch. Apply the same consistency rule to snapshot thumbnails and recipes.

   Code: [scheduled generation](src/app.js#L265), [doExport](src/app.js#L1151), [split export callbacks](src/app.js#L1167). Evidence: `deep.steps.js`, `transactions.steps.js`.

6. **Space hijacks native checkbox behavior.** Focus the Landscape checkbox and press Space. Landscape remains false while the seed changes. The shortcut handler excludes checkboxes from its typing guard but only exempts buttons in the Space handler. This affects every checkbox, including frame and optimization controls. Let interactive controls handle their native keys before applying global shortcuts. Add a keyboard test with real focus and key events.

   Code: [keyboard handler](src/app.js#L1393). Evidence: `deep.steps.js`.

7. **Image work cannot be reliably restored.** Load a PNG into Image, clear it with the X button, then undo. The filename returns as `qa-image.png (load again)`, but the image and drawing do not. Reloading after an upload similarly replaces the photo with the built-in demo. Saved recipes only carry the filename, and `imageStore` is memory-only.

   Reload behavior is partially acknowledged by the existing label, but it undermines snapshots and full-recipe restoration. Keep image assets in persistent storage and reference immutable asset IDs from undo history and snapshots. Portable exports need an embedded asset or an explicit missing-image state. Until then, avoid silently presenting the demo as the restored work, and retain cleared image data long enough for undo.

   Code: [imageStore](src/app.js#L151), [clear image](src/app.js#L655), [image loading](src/app.js#L680). Evidence: [image after reload](shots/qa-2026-09-29/transactions/image-reload.png), `deep.steps.js`, `transactions.steps.js`.

8. **TSP drawings are not deterministic across device speeds.** With the built-in image, seed 1, TSP mode, 20,000 points, and a 50 ms tour budget, normal and four-times-throttled CPU runs produced different geometry. Returning to the original speed reproduced the original result in this test. Switching seeds between runs avoided the in-memory tour cache.

   Both point relaxation and tour improvement stop according to wall-clock deadlines. Replace those limits with deterministic work budgets when reproducibility is required, or persist the generated geometry and clearly distinguish a time-limited mode. Tests that only regenerate a cached tour miss this case.

   Code: [point relaxation deadline](src/generators/image.js#L201), [tour deadline](src/generators/image.js#L368), [tour cache](src/generators/image.js#L535). Evidence: `http.steps.js`.

9. **Put QA checks before deployment.** The Pages workflow copies and deploys `src` without running either generator checks or browser smoke tests. Add the existing checks to pull requests and make deployment depend on them. Extend browser coverage to snapshots, file/share round trips, keyboard controls, and grid bounds. The existing smoke suite passes despite the findings above, so just running it is not enough.

   Code: [Pages workflow](../../.github/workflows/pages.yml#L23), [smoke checks](scripts/smoke.steps.js), [generator checks](scripts/check.js).

10. **Dialogs need focus management and accessible state.** Open the design gallery, focus the final card, and press Tab. Focus leaves the gallery; the next Tab reaches the Design button behind the overlay. Neither overlay has dialog semantics or a focus trap. The shortcuts overlay also leaves global drawing shortcuts active. Closing should restore focus to the opener. Add dialog labels, focus containment, and appropriate expanded/pressed state on menus and toggles. Snapshot deletion is a clickable span inside a button and also needs its own keyboard-accessible control once snapshots render.

    Code: [gallery markup](src/index.html#L182), [shortcuts markup](src/index.html#L195), [open/close gallery](src/app.js#L963), [snapshot deletion](src/app.js#L921), [keyboard handler](src/app.js#L1393). Evidence: `deep.steps.js`. This was a focused keyboard/DOM review, not a complete screen-reader audit.

11. **Move expensive generation off the UI thread.** A2 defaults took about 490 ms for Town and 948 ms for Fairground on this machine. A2 Town took about 1.71 seconds with four-times CPU throttling. Generation is synchronous, so controls and painting wait for completion. Debouncing helps repeated slider input but cannot keep the UI responsive during a run. The busy indicator also depends on the previous run's duration, so the first expensive transition may have no visible warning.

    A worker with cancellation and a result revision would improve large-paper editing and help solve the export race. Keep the current fast path in mind: most default A4 designs are already quick. These timings are measurements from one Windows machine and browser, not mobile-device benchmarks.

    Code: [requestGenerate/regenerate](src/app.js#L265), [pipeline](src/lib/pipeline.js#L280). Evidence: `touch-perf.steps.js`.

12. **Expose plotting costs already calculated.** The pipeline calculates drawing distance, pen-up travel, and pen lifts, but the status bar only shows paths, points, pens, and generation milliseconds. Showing those plotting metrics and per-pen distances would help users assess a long physical plot. Start there before adding time estimates, which would need machine-speed assumptions.

    Code: [status bar](src/app.js#L309), [plot statistics](src/lib/optimize.js#L223).

13. **Improve search and touch help.** Searching for a nonexistent design leaves a completely blank gallery body. Add a no-results message and a clear-search action. Parameter help is mostly a `title` tooltip on a question mark, which is hard to discover and use on touch. Make hints available through a small tappable/focusable control. Consider collapsing unused pen rows so active pens are easier to find on a phone.

    Code: [control hints](src/app.js#L494), [gallery filtering](src/app.js#L1040), [pen list](src/app.js#L841). Evidence: [empty phone search](shots/qa-2026-09-29/mobile390/06-empty-search.png).

14. **Clean up small publishing inconsistencies.** The app README says 32 designs while the loader and root README list 34. The deployment copies the unrelated `src/tetris.html` game into the public site. If that page is intentional, document it; otherwise keep it outside the published app. These are low-priority maintenance items.

    Code: [app README](README.md#L14), [Tetris page](src/tetris.html), [deployment copy](../../.github/workflows/pages.yml#L32).
